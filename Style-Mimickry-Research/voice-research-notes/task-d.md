## Findings
1. CosyVoice 2 unifies zero-shot reference cloning and natural-language instruction control in one model: a description (emotion, speaking rate, dialect, role) is prepended with an `<|endofprompt|>` token before the text [1].
2. CosyVoice 2/3 also expose fine-grained inline tags — `[laughter]`, `[breath]` vocal bursts and `<strong>...</strong>` emphasis / `<laughter>...</laughter>` — for phoneme-level prosody and non-verbals [1][2].
3. CosyVoice 3 scaled instruction-following data from 1,500 to 5,000 hours covering emotions, speed, tones, dialects, accents and role-play, but its 18+ accents are predominantly Chinese dialects (no native Irish-American category) [2].
4. Critically, CosyVoice cannot set *timbre* acoustically from text — only the reference clip controls voice character — so accent control beyond its trained dialect set is limited [1].
5. Fish-Speech OpenAudio S1 exposes 50+ inline emotion/tone markers including the ones we most need — `(whisper)`, `(soft tone)`, plus `(breath)`/`(sighing)`/`(panting)` non-verbals — to push delivery toward soft and breathy/wispy [3].
6. F5-TTS is reference-driven (1–5 s clip) and captures timbre/coarse prosody well, but zero-shot "flattens" rhythm and expressiveness, so the reference dictates accent more than any explicit knob [4].
7. StyleTTS2 represents speaking style as a diffusion-sampled latent style vector with tunable alpha (timbre) / beta (prosody) sliders, giving continuous style control conditioned on (or independent of) reference speech [5].
8. Parler-TTS is controlled purely by a natural-language *description* prompt (gender, pitch, rate, reverb, recording quality, and accent characteristics), but unnamed-voice consistency across sessions is not guaranteed [6].
9. In zero-shot TTS the reference clip carries the accent into the output, and aggressive neutralization (e.g. activation steering) risks "normalizing away" speaker characteristics — the accent and speaker identity are entangled [8].
10. Accent conversion (SpeechAccentLLM) disentangles content tokens from a separate timbre embedding, letting you change accent while *preserving* speaker identity (Sim-O rose 0.558→0.627 while accentedness dropped 25%) — confirming a path to keep a target timbre over a chosen accent [7].
11. Seed-VC does zero-shot timbre conversion from 1–30 s of target audio (fine-tune from 1 utterance / ~100 steps) and preserves source prosody, enabling a "record a modern actor, convert to target timbre" path — but it is GPL-3.0 (copyleft) [9].

## Deep Read Notes

### Controllability system — CosyVoice 2 [1] (with CosyVoice 3 deltas [2])
Two control surfaces coexist in one model: (a) **natural-language instruction** — a free-text description (emotion: happy/sad/angry/calm/serious; speaking rate: slow…very fast; dialect; role/persona such as mysterious, elegant, lonely) prepended before the synthesis text and terminated with `<|endofprompt|>`; and (b) **fine-grained inline tags** — `[laughter]`, `[breath]` vocal bursts placed between text tokens, plus `<strong>word</strong>` emphasis and `<laughter>...</laughter>` for laughing speech. Speaker *identity/timbre comes only from the reference audio or a speaker embedding* — text instructions cannot synthesize a new timbre, and the authors flag accent control outside the supported (mostly Chinese) dialect set as an open limitation, with degradation on overlapping character sets. CosyVoice 3 keeps the same interface but multiplies instruction-following data (1.5k→5k hrs) and accent/dialect coverage. **Implication for our case:** for a 1940s soft/wispy Irish-American persona, the *reference clip is the primary accent lever*; instructions are best used to layer "soft", "gentle", "slow", "breathy" style and to drop `[breath]` markers, not to invent the accent.

### Accent / voice-conversion approach — SpeechAccentLLM [7] (+ steering risk [8])
SpeechAccentLLM unifies foreign-accent conversion (FAC) and TTS over **discrete, speaker-agnostic content tokens** (CTC-guided codebook, strong "locality" so they carry linguistic content but not timbre), a separate **Speaker Encoder** for timbre, a joint FAC&TTS transformer decoder selected by task ID, and a SpeechRestorer to fix stochastic token errors. Because accent lives in the content/prosody stream and timbre is injected separately, the system reduces accentedness *while raising* speaker similarity (Sim-O 0.558→0.627, accentedness 2.48→1.86, WER 14.4%→9.1%, CMOS 3.55→4.07) — the explicit counter-example to the usual accent↔identity tradeoff. It needs little parallel data (9.3 hrs L2-ARCTIC, multitask with 370 hrs TTS incl. synthetic native speech). Limits: prosody modeling "not sufficiently comprehensive," timbre quality bounded by the pretrained speaker encoder, and SpeechRestorer can't fix skipped/repeated words. The companion steering paper [8] confirms the inverse risk: reference clips *do* inject accent, and forcing it out can strip authentic speaker character — so for *preserving* a specific historical accent we want the opposite of neutralization (a clean, accent-rich reference plus matching style prompts).

### Integration / SSML practice — ElevenLabs best practices [10] (+ Google SSML [12])
For long mimicker-generated text: **chunk on sentence boundaries** (keep segments ≤ ~20 s; ~60-char minimum chunks learn sentence-level prosody) and stitch results, sending sentences sequentially rather than one giant request. **Punctuation drives pacing** — ellipses `…` for weighted pauses, em-dashes for short breaks, line breaks for rhythm, capitalization for emphasis. **Normalize before TTS** (LLM or regex): expand money, phone numbers, dates, abbreviations like "Dr."→"Doctor", URLs; watch "Mr."/"Ave." falsely triggering sentence-end pauses. **Breaths/non-verbals**: older models accept `<break time="x.xs"/>` (and Google SSML `<break>`, `<prosody rate/pitch>`, `<say-as>` for numbers/dates [12]); newer tag-based models (Eleven v3, OpenAudio S1, CosyVoice) instead use inline tags like `[breath]`/`(whisper)` and *do not* support SSML breaks — so pick the pacing mechanism per engine. **Consistency across utterances**: reuse one fixed voice ID / reference embedding and identical settings (stability, speed 0.7–1.2) for every chunk; vendors note no reliable cross-request seed/determinism, so a *single frozen reference embedding* is the main consistency guarantee. JoyTTS [11] shows the LLM→TTS pattern end-to-end (LLM hidden states/speaker embedding feed the TTS), and recommends averaging segment embeddings (1,600 ms windows, 1,000 ms overlap) for a stable speaker vector.

## Gaps
- No open TTS exposes a native "Irish-American, 1940s" accent/era control; all evidence says the **reference clip is the only practical accent carrier**, and none of the surveyed systems have an explicit "era/decade" knob — period feel must come from reference selection + lexicon/pronunciation choices in the text, not a model parameter.
- Could not find a benchmarked result on cloning *toward a specific historical/dialect accent* from limited archival audio; accent-conversion papers target L2→L1 *neutralization*, the opposite direction, so applicability to "preserve and intensify a 1940s soft Irish-American voice" is unproven.
- Unclear how much CosyVoice/F5/StyleTTS2 "accent normalization" will erode a soft/wispy archival timbre when the reference is short and noisy; the steering paper [8] flags the risk but gives no measure for very-low-data archival inputs.
- Licensing caveat to verify for any production path: Seed-VC is GPL-3.0 (copyleft) [9]; CosyVoice/F5/StyleTTS2/Parler licenses were not re-confirmed in this pass and should be checked before integration.
- Sparse vendor-agnostic guidance on *deterministic* request stitching (seeds) for long multi-utterance documents; current best practice is only "freeze the reference embedding + identical settings."
