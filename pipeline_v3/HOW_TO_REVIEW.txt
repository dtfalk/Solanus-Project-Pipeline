================================================================================
HOW TO REVIEW + HOW THE verify-visual-labels SKILL WORKS        (2026-06-14)
Run everything from:  pipeline_v3/step_4
================================================================================

There are TWO separate things here:
  A. YOU reviewing pages in the editor and saving gold.
  B. The verify-visual-labels SKILL — the method *I* (Claude) use to actually
     SEE whether boxes are right, and that YOU can run yourself to zoom-inspect.


--------------------------------------------------------------------------------
A. DOING THE ACTUAL REVIEW (contents pages — flip variants, pick one, save)
--------------------------------------------------------------------------------

1. Open a volume's contents pages with all snap versions to flip between:

      ./venv/bin/python review_variants.py Appendix_2
   (volumes available: Volume_1, Volume_2, Appendix_1, Appendix_2, Appendix_3)

   It pre-builds raw / medium / gentle from the saved raw (instant, no API) and
   opens the editor on that volume's contents pages, starting on MEDIUM.

2. In the editor:
     - Tab  (or the "◀ variant ▶" button)  = flip raw -> soft -> medium ->
                                              your saved "reviewed✓" copy
     - edit the active version normally (drag, arrows to tighten, Shift-click to
       relabel, S/W = next/prev box, A/D = prev/next page)
     - "✓ Save this -> gold"  = writes the version currently shown into reviewed/
       AND designates it the gold working copy.

   HOW SAVING WORKS NOW (the lost-work fix — read this):
     - The reviewed/ file is written ONLY from the ONE variant you designated as
       gold: the variant you pressed "✓ Save this -> gold" on, or — before any
       explicit save — the first variant you actually edit.
     - Auto-save (paging A/D, flipping Tab, closing) persists THAT gold variant's
       edits. Flipping to 'raw' to compare and nudging it can NO LONGER overwrite
       the good version you built on 'soft' — comparison edits are not written to
       gold. To make a different variant gold, press "✓ Save this -> gold" on it.
     - EVERY overwrite first copies the previous file to
         reviewed/<Vol>/page_NNN/.backups/page_NNN.<timestamp>.json   (newest 40)
       so a bad save is always recoverable:
         ./venv/bin/python restore_reviewed.py list Volume_1 3   # show backups
         ./venv/bin/python restore_reviewed.py Volume_1 3        # restore newest
         ./venv/bin/python restore_reviewed.py Volume_1 3 --ts 20260614-141233

3. Non-contents pages (normal review of any volume):
      EDITOR_DOCUMENT=Volume_4 ./venv/bin/python normalized_editor.py
   (worst-first list, if present: qa_output/<Vol>/triage.txt)


--------------------------------------------------------------------------------
B. THE verify-visual-labels SKILL  (so labels are actually checked, not guessed)
--------------------------------------------------------------------------------

WHERE IT LIVES:  ~/.claude/skills/verify-visual-labels/
                 (SKILL.md = the method;  overlay_inspect.py = the tool)

HOW IT "ACTIVATES":
  - It is MY skill. It triggers automatically when I'm asked to judge whether
    boxes/labels are correct, bleed, clip, or to compare label versions.
  - To force it, just tell me:  "verify <page> with the verify-visual-labels
    skill"  — and I will crop-zoom-overlay and report per-box findings instead
    of guessing from a thumbnail or a statistic.
  - You do NOT install anything; it's already on disk and persists across
    sessions.

WHY IT EXISTS (the bug it fixes):
  A whole-page render gets downscaled by the vision model to ~1568px; your pages
  are ~5000-7000px, so a clipped letter or a box overrunning by ~40px becomes
  sub-pixel = invisible. That's why "looks fine" kept being wrong. The skill
  forces small high-zoom crops where the errors are actually visible.

YOU CAN RUN THE INSPECTOR YOURSELF (zoom-inspect any page's labels):

  # 8 stacked high-zoom strips with thick boxes + a margin so bleed shows:
  ./venv/bin/python ~/.claude/skills/verify-visual-labels/overlay_inspect.py \
      reviewed/Appendix_2/page_003/page_003.pdf \
      reviewed/Appendix_2/page_003/page_003.json --tiles 8
      -> writes /tmp/inspect_00.png .. inspect_07.png  (open them)

  # zoom ONE box to the max, with neighbours + connections:
  ... overlay_inspect.py <page.pdf> <labels.json> --box doc_1:archv_date:4

  # overlay a reference (gold) dashed on top, to diff visually:
  ... overlay_inspect.py <page.pdf> <labels.json> --gold <other.json>

  (Use a page.pdf + labels.json from the SAME folder: reviewed/, auto_labeled/,
   or snap_compare/<raw|medium|gentle>/<Vol>/page_NNN/.)

THE RULE (mine, and yours if you inspect): never judge from the full page; crop
+ zoom; check each box for clip / bleed / wrong-category / wrong-connection;
state the specific box that's wrong. "Looks fine" at low zoom = not verified.
