------------------------------------------------------------------
THE BUG (found 2026-06-19)
------------------------------------------------------------------
Symptom: on a page, the labeled boxes are there but some boxes (the non-"src" ones,
e.g. archv_commentary / archv_date — the archivist's framing notes) render BLANK in the
masked PNG/PDF, even though they have text in the step_4 editor.

Root cause: masking ran on the WRONG source image.
  - The gold labels were drawn in step_4's normalized_editor, whose SOURCE_DIR is
    step_4/auto_labeled/<Vol>/page_NNN/page_NNN.pdf  (verified: this PDF HAS the archival text).
  - But masking (and the page-PDF population) used
    step_4/polygon_cropped_pdfs/<Vol>/pages/page_NNN.pdf  — a cropped variant that is BLANK
    in the archival-framing area.
  - So every polygon was kept (nothing dropped), but the archival regions had no pixels to
    keep -> they masked out blank.

Fix: mask from auto_labeled (the editor's input), the source the labels correspond to.

------------------------------------------------------------------
WHAT CHANGED IN THE CODE (already committed in this push)
------------------------------------------------------------------
mask_pages.py
  - Source is now step_4/auto_labeled/ (was polygon_cropped_pdfs/). ensure_src_pdf() ALWAYS
    re-links each page's PDF from auto_labeled, so the stale/wrong source PDFs get corrected.
  - Run with --force to regenerate ALL masks (the existing masks are from the wrong source).

extract_azure.py
  - Per-word OUTPUT now includes each word's page-pixel box: words=[{t, c, box:[x0,y0,x1,y1]}].
  - Writes the full RAW Azure responses too: extract_azure.raw.json (both passes, nothing discarded).
  - Summary now reports "<0.90 conf: N words in M regions" (was region-only).

review_ocr.py
  - RIGHT pane now places every OCR word at its ACTUAL page position (1:1 spatial compare),
    sized per word, typewriter monospace (Courier Prime), low-confidence words highlighted
    (amber <0.90, red <0.70). Edits persist with positions in extract_azure.reviewed.json.

enrich_pages.py  (unchanged this round; recap)
  - Builds 3_enriched/ from 2_src_organized/. Folders+files named by pdf_page_number (Option A);
    JSON keys: source_file (bare doc name), pdf_page_number, page_type, page_number_in_type,
    dims..., documents last. Per-section page_index.json manifest. Modes: default overwrite /
    --no-overwrite / --fresh / --dry-run.
