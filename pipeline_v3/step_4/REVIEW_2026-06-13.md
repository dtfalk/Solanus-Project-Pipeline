## 2. The bounding-box bleed — the project's #1 issue, diagnosed and fixed

**Problem (David, recurring across the whole project):** boxes are too big — a box swallows the
ellipses/leader-dots, or a header box bleeds into the next line (recipient → location → …), so
one polygon contains another's ink. On tightly-packed pages this makes review miserable.

**Root cause (proven, not guessed).** The culprit is the `snap_polygon_to_ink` post-processing,
specifically its **gap-bridging** and **wide search reach**, which were tuned aggressively in the
flash-lite era to fix the *opposite* problem — clipping (boxes cutting off line-ends, "missing
text"). It is a precision/recall lever that had been set hard toward recall. Decisive test: run
snap on David's **already-perfect gold** (no model involved) and measure how far it moves correct
boxes:
- contents descriptions: **every** box grew rightward a median **+654px** (max +813) — ballooning
  across the leader dots to the next column;
- contents dates: **+366px**;
- letter headers: `src_recipient` **+82px** down, `src_location_recipient` **+83px** up & +362 right.

The mechanism: leader dots / closely-stacked lines are *ink*, and `h_gap_frac`/`v_gap_frac` bridge
the small gaps between them into one run that the box then follows; the wide `margin_frac` reach
lets it travel; the only thing that stops it is a neighbouring box (fence), so it fills the whole
gap up to the next column/line. Snap literally re-loosens hand-tight boxes.

**Why it's a real tradeoff — and how it's escaped.** Reducing the gap/reach globally cuts the
over-extension 94% (654→37px) but clips ~10/38 `src_content` *bodies* (multi-line paragraphs
genuinely need the reach to catch wrapped lines). The escape: **the over-extension is in
single-line categories; the recovery need is in multi-line bodies — different categories.** So snap
is now **category-aware**:
- single-line categories (recipient, locations, dates, greeting, signature, descriptions, page
  markers, …) → tight params (no dot-bridging, small reach);
- multi-line bodies (`src_content`, `src_origin` letterheads) → keep the aggressive params.

**Three snap modes now exist (`--snap-mode`):**
- **raw** — the model's boxes, no fit-to-ink.
- **gentle** — tight for single-line categories, aggressive only for bodies.
- **medium** — the *geometric midpoint* between raw and gentle (each box moved halfway). This is
  the safe default for review: tighter than raw, but won't clip like gentle.
- (`current`, the old aggressive snap, was **removed** from the review variants.)

**Second, deeper finding (from actually looking at pixels — see §7).** On *contents* pages the
over-extension was largely the **model itself** drawing across the dots, not snap. The fix there is
the **prompt note**, not geometry: `volume_notes/_contents_page.md` now explicitly says end each
box at the last letter and leave the dot leaders outside every box. After that, **raw** contents
output is clean (dots excluded, full text), and gentle snap actually *added* harm — it clipped
"Notebook No. 11 :" to "Notebook No." (919px raw → 679px gentle). Lesson: snap helps letters
(where the model draws tight and snap over-extends); for contents the note does the work and snap
should be light (raw/medium).

## 4. Contents/index pages unified to one template

**Problem.** Contents pages were labeled inconsistently across the corpus (some descriptions as
`src_content`, some `archv_commentary`; dates present or not; only one of three connection types),
and they are the densest, most painful pages to fix by hand.

**Schema (from David's page_006 gold, studied box-by-box).** Each row is a **triangle**:
`archv_commentary` (left description) ↔ `archv_date` (middle) ↔ `struct_doc` (right page number),
all three connected; a description *heading* governs every dated row beneath it until the next
heading (fan-out). "VOLUME II"/"CONTENTS" = `struct_id`; "Pages" header = `struct_other`.

**Solution.**
- `volume_notes/_contents_page.md` — the convention as a prompt note (categories + exclude the dots).
- `contents_connect.py` — wires the row triangle **geometrically** (no model): reproduces the gold
  connections at **95–96%**, handling both fan-out (dated rows under a heading) and 1:1 layouts.
- `relabel_contents.py` — labels each page (page_006 pinned + the note) then wires the triangle;
  writes `auto_labeled/` only. All 17 contents pages relabeled tight (dots excluded, verified).
- The connection whitelist + pass-2 prompt were extended for the contents edges that David's gold
  uses but the model had been *forbidden* from producing (`archv_commentary↔struct_doc` was being
  silently dropped — a real bug from Iter 12 that never reached the connection layer).

**Known residual:** on heavily **skewed** pages the geometric connector pairs date↔page by vertical
position with a tolerance and can mis-pair. David's rule ("follow the ellipsis line") is the correct
fix; building the connector to follow the dot-leader baseline is the open improvement that would
most reduce connection edits.

## 5. Raw model output is now saved as an intermediate

**Problem (David).** Comparing snap modes re-called the model every time — slow, costly, and not
even a fair comparison (temperature 0 is not perfectly deterministic, so the raw boxes differed
between runs).

**Root cause.** `process_page` ran model → snap → backstop → connections and saved only the final
result; the raw model boxes were thrown away.

**Solution.** `process_page` now writes `page_NNN.raw.json` (raw boxes, pre-snap) beside each page.
`apply_post.py` re-applies any snap mode (+ the contents triangle) to that saved raw with **no model
call** — it produced all three versions of 17 pages in **16 seconds** vs ~35 minutes, and the
comparison is fair (identical raw boxes). This cleanly separates *inference* (expensive, once) from
*post-processing* (cheap, repeatable).

## 6. Variant editor — flip between versions, save your pick

**Problem (David).** Wanted to pre-run each version, flip between them in the editor, edit the
active one, and choose which to save to gold.

**Solution.** `normalized_editor.py` VARIANT MODE (`EDITOR_VARIANTS=...`): loads every pre-run
version of a page; **Tab** (or the "◀ variant ▶" button) flips raw → medium → gentle → your
`reviewed✓` copy; each variant keeps its own edits while you flip; **"✓ Save this → gold"** writes
the chosen version to `reviewed/`. `review_variants.py <Vol>` builds the three versions from saved
raw (instant) and launches it on that volume's contents pages; opens on **medium**.

**Save bug fixed (the "didn't stick").** Variant mode had been auto-saving the *displayed* variant
on page navigation, so saving raw→gold then flipping to gentle and paging overwrote the pick with
gentle. Now: **no auto-save on navigation in variant mode** (explicit save only); the saved page
becomes `reviewed✓` and shows first on return; flipping updates the baseline so no stray writes.

## 7. Process lesson — judge pixels, not aggregates

The bleed survived many "checks" because they were **aggregate metrics** (median pixel offsets, box
counts), which can look fine while individual boxes are wrong. When the boxes were actually examined
at the pixel level, the real failures surfaced in minutes (the title clip, that raw is cleaner than
gentle for contents, that the model — not snap — drew across the dots). Standing rule for this
codebase: **verify by rendering and reading individual boxes against the page, not by summary
statistics.** Coordinate-shift claim was checked this way too: measured ~0px aggregate shift (no
coordinate bug); ~7–11% of boxes the model places low, which snap corrects.
