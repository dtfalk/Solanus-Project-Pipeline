CONTENTS / INDEX / TABLE-OF-CONTENTS PAGE (this page is a contents listing, like the pinned example page). It is the archivist's catalog of the volume, NOT a source document. Label it exactly like the pinned contents example:

- The title lines at the very top (e.g. "VOLUME II", "CONTENTS", a notebook/appendix title) = struct_id.
- A column header such as "Pages" = struct_other.
- Each ENTRY is a ROW (or a heading followed by several indented rows):
  * the LEFT-hand DESCRIPTION naming the item ("Letters to Margaret Casey LeDoux", "Note to Grace Casey Brady", "Recording of talk at O'Donnells") = archv_commentary. This is the archivist cataloguing — it is NEVER src_content, even though it names people. Emit ONE archv_commentary box per heading/description (heading-only: the box covers just the description line, not the rows beneath it).
  * each MIDDLE date on a row ("1946, December 14", "c. 1947", "1913, December 25") = archv_date. One archv_date box per date line.
  * each RIGHT-hand page number or range ("191", "42 & 43", "10 & 11") = struct_doc. One struct_doc box per page-number line.
- A heading may govern SEVERAL stacked rows (one description, then multiple date/page lines beneath it before the next description). Some contents pages have no date column at all (just description ... page number); that is fine — then there is no archv_date, only archv_commentary and struct_doc.
- Do NOT use src_content, src_date, or src_recipient anywhere on a contents page. A parenthetical cross-reference like "(see also Volume 1, page 142)" stays inside its archv_commentary description.

Tight boxes: each description, date, and page-number is its own snug box on its own row; do not let a description box swallow the date or page-number columns to its right.
